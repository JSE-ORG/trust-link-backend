# Issues #1140, #1144, #1145, #1147 — Implementation Notes

## #1144 — GET / no longer returns "Hello World!"

**File:** `src/app.service.ts`

`AppService.getInfo()` replaces `getHello()`. The method returns a `ServiceInfoDto`
with three fields:

| Field | Type | Notes |
|-------|------|-------|
| `name` | `string` | Always `"trustlink-backend"` |
| `version` | `string` | From `npm_package_version`; falls back to `"0.0.0"` |
| `docsPath` | `string \| null` | `/api` when `SWAGGER_ENABLED` is truthy and `NODE_ENV !== "production"`, otherwise `null` |

`AppController.getHello()` must be updated to call `appService.getInfo()` and
its `@ApiOkResponse` changed to `type: ServiceInfoDto`. The existing throttle
(`limit: 100`) stays in place.

## #1140 — Seven routes missing `@ApiResponse({ status: 429 })`

The following routes have `@Throttle(...)` but no 429 declaration in the
OpenAPI document. Add `@ApiResponse({ status: 429, description: 'Too many requests.' })`
to each one:

| Controller file | Route |
|-----------------|-------|
| `src/admin/stats/admin-stats.controller.ts` | `GET /admin/stats` |
| `src/admin/dispute/dispute.controller.ts` | `GET /admin/disputes` |
| `src/admin/dispute/dispute.controller.ts` | `PATCH /admin/dispute/:id/resolve` |
| `src/admin/dispute/dispute.controller.ts` | `GET /admin/audit-log` |
| `src/admin/queues/queue-dashboard.controller.ts` | `GET /admin/queues` |
| `src/admin/api-keys/api-keys.controller.ts` | `PATCH /admin/credentials/logistics` |
| `src/webhooks/stellar-webhook.controller.ts` | `POST /webhooks/stellar` |

> **Note on `POST /webhooks/stellar`:** the route uses `@SkipThrottle()` (issue #923)
> so it is never actually rate-limited at runtime. The `@ApiResponse(429)` decorator
> should still be added so the OpenAPI document is consistent, but a code comment
> must explain that the limiter is bypassed in production.

**Decorator to add** (identical for all seven):

```ts
@ApiResponse({ status: 429, description: 'Too many requests.' })
```

Place it immediately after the last existing `@ApiResponse` decorator on each
route handler, before `@Throttle` / `@SkipThrottle`.

## #1145 — Terminal Africa logistics provider

**Location:** `src/logistics/terminal-africa/`

Pattern follows `src/logistics/gigl/` exactly. Three files are required:

### `terminal-africa-client.ts`
Thin HTTP wrapper around the Terminal Africa Tracking API.

```ts
export class TerminalAfricaClient {
  constructor(private readonly baseUrl: string, private readonly apiKey: string) {}

  async getTracking(trackingNumber: string): Promise<TerminalAfricaTrackingResponse> {
    // GET {baseUrl}/v1/track/{trackingNumber}
    // Authorization: Bearer {apiKey}
  }
}
```

### `terminal-africa.types.ts`
Raw API response shapes + mapping function to `TrackingDetails`.

Status mapping (Terminal Africa → canonical):

| Terminal Africa status | Canonical `TrackingStatus` |
|------------------------|---------------------------|
| `PENDING` | `pending` |
| `PICKED_UP` | `in_transit` |
| `IN_TRANSIT` | `in_transit` |
| `OUT_FOR_DELIVERY` | `out_for_delivery` |
| `DELIVERED` | `delivered` |
| `FAILED_DELIVERY` | `failed` |
| `RETURNED` | `returned` |
| `CANCELLED` | `cancelled` |
| _(unknown)_ | `unknown` |

### `terminal-africa.service.ts`
Implements `LogisticsProviderInterface` (`getStatus`, `getTrackingDetails`).

### Config keys (add to `src/config/config.schema.ts` and `.env.example`)

```
TERMINAL_AFRICA_BASE_URL=https://api.terminal.africa   # optional
TERMINAL_AFRICA_API_KEY=                               # optional, secret
```

Both keys are optional — when absent the service throws `LogisticsProviderUnavailableException`.
GIGL remains the bound provider; Terminal Africa is registered but not injected
as the default `LogisticsService`.

## #1147 — Cache escrow reads (R-CA-01, R-CA-03, R-CA-04)

**Config key:** `ESCROW_CACHE_TTL_SECONDS` — integer, default `60`, max `60`.
Add to `src/config/config.schema.ts` and `.env.example`.

### Cache key convention
```
escrow:{id}
```

### Read path (`src/escrow/escrow.service.ts`)

`findById(id)`:
1. `const cached = await cacheService.get<EscrowResponseDto>('escrow:' + id)`
2. If hit → return cached.
3. If miss → call `escrowRepository.findById(id)` → store result with TTL → return.

When Redis is not configured (`CacheService` is a no-op) the behaviour is unchanged.

### Write / invalidation path (`src/escrow/escrow.repository.ts`)

After every method that mutates an escrow row, call:
```ts
await this.cacheService.del('escrow:' + id);
```

Methods that must invalidate:

| Method | Trigger |
|--------|---------|
| `updateState` | Any state transition |
| `markFunded` | Funds confirmed |
| `markReleased` | Release confirmed |
| `markRefunded` | Refund confirmed |
| `markAutoReleaseSubmitting` | Auto-release queued |
| `markAutoReleased` | Auto-release confirmed |

### Tests required

| Test | Assertion |
|------|-----------|
| Cache hit | Second `findById` call does not reach the repository |
| Cache miss | Repository is called; result is stored |
| Read after `updateState` | Returns fresh data (cache was invalidated) |
| Read after `markFunded` | Returns fresh data (cache was invalidated) |
| Redis disabled | `findById` delegates directly to repository, no error |
